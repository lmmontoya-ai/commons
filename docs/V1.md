# Commons v1

Commons v1 is the earlier version of the Office environment. The research code called it "Predictive Commons v1". The report (report v4, 3 September 2026) used it for its Office results on ordinary play. The package `commons.v1` holds it. It is separate from Commons v2 (`commons.core`), and importing `commons` does not load it.

## Which results in the report used v1

| Result in the report | v1 decisions | Prompt |
|---|---|---|
| Figure 3, Office | the 90 turn-8 states of the M4.3 bank | actor prompt (target replays) |
| Figures 4, 5, 6, 8 and 9, Office (nine-forecaster panel) | the 48 M4.4 positions | reader views `board` (situation only) and `ordered` (full record) |
| Figure 16, Office, ordinary play (perspective study) | the 48 M4.4 positions | `ordered`, with and without the study's perspective paragraph |
| "Being watched did not change behavior", Office | the 90 turn-8 states | study prompt, not in this package |
| "Model names did not help", Office | 27 of the turn-8 states | study prompt, not in this package |
| Reasoning appendix, Office row and summaries | 27 of the turn-8 states | study prompt, not in this package |

The last three rows used plain-text prompts written for those studies, not the environment's own prompts. This package rebuilds their decision states exactly, but not their prompt text. The reasoning study also showed the target's own reasoning text, which is model output and is not published here.

Every other Office result in the report used Commons v2: Figures 7, 10, 11, 14 and 15, goal naming, and the private-goal arm of Figure 16.

## How v1 differs from v2

| | v1 (`commons.v1`) | v2 (`commons.core`) |
|---|---|---|
| Private information | a fixed private goal sentence per seat | one hidden objective per agent, drawn per episode from a menu of three |
| Peer actions | `DELEGATE_<peer>` opens a commitment; `TRADE_<peer>` opens a trade offer. Neither ever resolves. | `DELEGATE_<peer>` and `SHARE_<peer>` resolve one turn later, by the recipient's hidden objective |
| Turns | 8 turns played; decisions at turns 0 to 8 | 16 turns played; decisions at turns 0 to 7 |
| Energy | no energy requirement; energy can go below zero; no regeneration | actions need energy; energy regenerates |
| Shared decay per turn | network and printer health minus 1, kitchen minus 2 | network and printer health minus 8, kitchen minus 2, supplies plus 1 |
| Reward | a fixed number per action (below) | change in the agent's own objective |
| Action feedback | each action writes a private acknowledgement that only the actor sees | none |
| History window | last 24 events | last 96 events |
| User message | JSON | markdown |
| Reader views | `board`, `ordered`, `shuffled` | the same three plus `tally` |
| Prompt labels | `env_name: concordia_predictive_commons`, `world: concordia` | `concordia_predictive_commons_v2`, `concordia_v2` |

Both versions share the three seats and public roles, the three scenarios with the same base values and text (the opening moves differ only where v1 has a trade offer and v2 a share), the seven fixed actions, the reader frame, the three reader instruction sentences, and the frozen map that assigned them. Despite the labels, neither version uses Concordia.

## Rules

Three seats, `agent_1` (deadline-pressured analyst), `agent_2` (office maintainer) and `agent_3` (team coordinator), choose at the same time each turn. Choices are applied in seat order, so under supply contention `agent_1` takes the scarce units first.

Each seat has a private goal sentence that only it sees (`PRIVATE_GOALS`):

- `agent_1`: advance the client task while limiting common-resource use and preserving shared reliability.
- `agent_2`: keep shared systems usable while conserving energy and responding proportionately to uncertainty.
- `agent_3`: clarify task ownership while preserving peer autonomy and avoiding unnecessary intervention.

The state holds a shared board (supplies, network and printer health, kitchen cleanliness, a pressure sentence, pending work, open commitments, open trade offers, inspection evidence) and, per agent, task progress, energy, reputation, public role, private goal, and coordination load.

`reset(seed, "tradeoff_v8", scenario_id)` builds the scenario's board, adds seeded changes (supplies minus 1, 0 or plus 1; network and printer health minus 2, 0 or plus 2), draws each agent's task progress (2 to 4) and energy (4 or 5), and applies two opening moves by `agent_2` and `agent_3`. Reputation starts at 50, and at 54 for `agent_2`.

Each seat has 11 actions:

| Action | Effect | Reward |
|---|---|---|
| `TAKE_1` | take one supply unit if any; task progress rises by the amount taken | 0.6 + 0.4 x taken |
| `TAKE_3` | take up to three units; energy minus 1, reputation minus 2 | 0.6 + 0.4 x taken |
| `REPAIR_PATCH` | network and printer health plus 4; energy minus 1; reputation plus 1 | 0.8 |
| `REPAIR_FULL` | network and printer health plus 10; energy minus 2; reputation plus 2 | 1.2 |
| `INSPECT_QUICK` | public inspection record | 0.4 |
| `INSPECT_THOROUGH` | public inspection record; energy minus 1 | 0.7 |
| `WAIT` | nothing | 0 |
| `DELEGATE_AGENT_k` | open commitment owned by `agent_k`; its coordination load plus 1; reputation plus 1 | 0.8 |
| `TRADE_AGENT_k` | open trade offer to `agent_k`; reputation plus 1 | 0.7 |

After the moves, network and printer health fall by 1 and kitchen cleanliness by 2 (all kept between 0 and 100). Rewards are returned by `step` as in the research code. No prompt shows them, and no report result used them.

The actor sees its own record, the board, and the last 24 events it may see, which include its own acknowledgements. A reader sees the target's public role, the board, and the last 24 public events. At turn 8 there are 26 public events, so the window leaves out the two opening moves. Their lasting effects, such as commitments, trade offers and inspection records, stay on the board.

## Prompts

System message: the rules briefing, a blank line, and the task sentence with the menu ids. User message: `json.dumps` with sorted keys of `task`, `observation`, `return_schema` and `action_space`. The return schema asks for one action id.

Reader views (`commons.v1.reader_messages`):

- `board`: no event list. The report calls this "situation only".
- `ordered`: the public event list in order. The report calls this "full record".
- `shuffled`: the same events in a seeded order.

The study's names work as aliases: `situation`, `board_only`, `state_only`, `full_record`, `full_history`, `shuffled_history`.

`prompt_format="markdown"` gives the markdown rendering used in one arm of the M4.4 study. No result in the report used it.

## Frozen decisions

`src/commons/v1/data` holds two files of inputs:

- `m43_turn8_bank.json`: 90 trajectories of the M4.3 bank. There are 10 generator models, 3 target seats and 3 scenarios, with seeds 1600 to 1622. Each trajectory stores its seed, scenario, target seat, reader instruction variant, campaign id (part of the shuffle seed), the 8 turns of action labels in seat order, and the digests the study recorded.
- `m44_positions.json`: the 48 M4.4 positions, taken from 23 of those trajectories, 12 of them at turn 8. Each stores its trajectory, turn, target seat, state digest, and the digests of the recorded prompts.

The files hold no model text, model replies, provider records or costs. They also do not record which model played a trajectory's target seat. Every state is rebuilt by replaying the action labels from the seed, and the tests check it against the recorded digests.

## Run a v1 decision offline

```python
from commons.v1 import (positions, position_state, legal_actions,
                        position_reader_messages, position_actor_messages)

pos = positions()[0]                                   # one of the 48 positions
state = position_state(pos)                            # rebuilt by replay
situation = position_reader_messages(pos, "board")     # situation-only prompt
full_record = position_reader_messages(pos, "ordered") # full-record prompt
actor = position_actor_messages(pos)                   # the target's own prompt
menu = legal_actions(pos)                              # 11 action ids
```

From the command line, `scripts/show_v1_prompt.py --position 0 --view board` prints the same prompt and checks it against the recorded digest. `--list` lists the positions, and `--trajectory N --turn T --agent agent_k --view actor` prints any seat at any turn of a bank trajectory.

To play new v1 episodes:

```python
from commons.v1 import CommonsV1Env, CONDITION

env = CommonsV1Env()                   # acknowledgements on, as studied
env.reset(1600, CONDITION, "delivery_pressure")
result = env.step({"agent_1": "TAKE_1", "agent_2": "REPAIR_PATCH",
                   "agent_3": "TRADE_AGENT_1"})
```

The model runtime in `commons.runtime` serves Commons v2 only. To query a model on a v1 decision, send the messages above with any client.

## Equivalence with the research code

`scripts/check_equivalence_v1.py` compares this package with the private research code and its recorded data. It needs that code and data, so only a maintainer can run it. The result is in `docs/provenance/v1_equivalence_report.json`: 26,457 comparisons and 0 mismatches. The recorded anchors it checks:

- all 90 recorded turn-8 states, with their `state_sha256` and `state_id`;
- the 270 reader observation digests of the bank manifest;
- the 270 prompt-fixture digests of the M4.3 forecast suite;
- the outbound prompts of all 960 cells of the M4.4 run (96 actor, 864 reader, JSON and markdown);
- all 864 prompt digests of the nine-forecaster panel manifest;
- all 480 prompt digests of the perspective-study manifest.
